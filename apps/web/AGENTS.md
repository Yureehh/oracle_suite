# Website rules

Prefer TypeScript and Next.js when implementation begins, subject to the frontend
specification. Prioritize accessibility, responsiveness and performance. Separate UI
components from computational logic and keep expensive model workloads out of browser
request handlers.

Reuse UI patterns, maintain a coherent Strixia identity with room for branding, and
make loading, failure and empty states explicit. No fake live dashboards or fabricated
data. Do not initialize a frontend solely to fill this directory.
