### Decision and edge-case register — discussion 2026-10-13

Owner supports complete paired choices, excluding known-invalid choices and preserving
player-visible uncertainty. Sequential encoding must not become greedy selection or
prune valid pairs. Policy architecture and value estimation remain later stories.
The following register is an evolving coverage list, not a claim of tested support.

| Case | Evidence / remaining work |
| --- | --- |
| Both slots select the same reserve | Pinned `sim/side.ts` rejects duplicate switch-ins; engine acceptance and enumeration checks pass |
| Both slots spend Mega evolution, including X/Y variants | Pinned `sim/side.ts` shares the Mega flag; M-C Mega X/Y stones and pair tests pass |
| Both slots request Z-Moves | Pinned `chooseMove` rejects duplicate Z usage; Champions item legality must gate exposure |
| Both slots request Dynamax / already-Dynamaxed moves | Pinned `chooseMove` checks shared usage and generation; not automatically an M-C feature |
| Both slots request Terastallization | Pinned `chooseMove` checks shared usage; Champions action override disables Tera |
| Ultra Burst and combinations of different special mechanics | Pinned engine has separate resource flags; inspect format eligibility rather than assuming all mechanics share one flag |
| Hidden or uncertain trapping | Pinned request supports `maybeTrapped`; masking must not inspect hidden state |
| Rejection reveals a restriction | Pinned `chooseSwitch`/`chooseMove` can update requests; current adapter rollback loses updates; corrected and real trapping/Imprison tests pass |
| Perish Song plus trapping / switching availability | Scenario requested by owner; fixture and Champions legality verification pending; do not confuse bad strategy with illegal switching |
| Disabled, locked or exhausted moves; Struggle | Pinned request supports relevant restrictions; projection and enumeration coverage pending |
| Move targets: self, ally, opponents, automatic/spread | Derive target rules from pinned engine; tests pending |
| Forced switches, fainted slots, too few reserves, waiting | Adapter has basic forced-switch evidence; complete pair/phase coverage pending |
| Preview selections and lead order | Enumerate permitted complete selections; retain strategically distinct orders |
| Stale choices and repeatability | Bind choices to their request; stable ordering and stale-choice tests pending |
| Hidden worlds with identical visible requests | Candidate menu must match; offline validation must not become a live hidden-state oracle |
| Misses, Protect, immunity, redirection and opposing choices | Distinguish legal selection from resolution failure; do not remove legal strategic risks |

A live trial against omniscient engine state must not expose its accept/reject verdict
for every candidate to the policy. Use player requests for the menu, offline engine
checks for correctness, and protocol-permitted request updates after actual submissions.
